Install once

Recommended: guided install

Run this from any directory. Claude Code stays interactive so you can review and approve anything it needs through the normal permission flow.

claude "Install EFWH from https://github.com/ZacharyThrasher/evidence-first-work-harness for me. Follow the repository's INSTALL.md and guide me through any approvals."

Claude follows the repository's INSTALL.md, installs EFWH at personal scope, handles an existing copy safely, verifies the installed version, and tells you if one Claude restart is needed for discovery.

Deterministic manual fallback

If you prefer a non-agentic install, use the platform script:

Windows / PowerShell

git clone --depth 1 https://github.com/ZacharyThrasher/evidence-first-work-harness.git efwh
& .\efwh\scripts\install.ps1

macOS / Linux

git clone --depth 1 https://github.com/ZacharyThrasher/evidence-first-work-harness.git efwh
./efwh/scripts/install.sh

The fallback installers honor CLAUDE_CONFIG_DIR when set; otherwise they install to ~/.claude/skills/efwh/. They refuse to overwrite an existing install unless force is explicitly requested.

Use it

Start Claude Code in the repo, analysis folder, or document workspace where the work should happen:

/efwh <problem in normal language>

Optional controls:

/efwh --autonomy advisory <goal>
/efwh --autonomy experiment --rigor high <goal>
/efwh --autonomy builder <goal>
/efwh --autonomy sandbox --rigor high <goal>
/efwh --resume
/efwh --status

No GOAL/config file editing is required. EFWH writes its durable project state under .efwh/.

For company-managed deployment, see reference/company-rollout.md.

That’s the workflow. Install once, then start Claude Code where the evidence lives and type /efwh <problem>.
